Executive Summary

This report outlines a phased migration from our current monolithic Rails application to a service-oriented architecture. The primary drivers are deployment velocity (currently 2-week cycles due to coupled test suites), scaling costs (vertical-only scaling on the monolith), and team autonomy (three product teams contending for the same deploy queue).

We recommend a strangler fig pattern executed over four quarters, extracting services in order of business value and lowest coupling first. The estimated total cost is $1.2M in engineering time with a break-even at month 14 from reduced infrastructure spend and faster cycle times.

Key risks include database decomposition (currently 140+ tables in a single Postgres instance), inter-service authentication, and maintaining data consistency during the transition window when both systems write to overlapping domains.

Target Architecture

The target state replaces the monolith with six services behind an API gateway. The gateway handles auth, rate limiting, and request routing — each downstream service is responsible only for its domain logic and data.

┌─────────────────────────────────────────────────────────┐ │ API Gateway (Kong) │ │ auth / rate-limit / routing │ └──────┬──────────┬──────────┬──────────┬─────────────────┘ │ │ │ │ ▼ ▼ ▼ ▼ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────┐ │ Auth │ │ Billing │ │ Orders │ │ Inventory │ │ Service │ │ Service │ │ Service │ │ Service │ │ (Go) │ │ (Go) │ │ (Rust) │ │ (Rust) │ └────┬─────┘ └────┬─────┘ └────┬─────┘ └──────┬───────┘ │ │ │ │ └────────────┴────────────┴───────────────┘ │ ┌───────┴───────┐ ▼ ▼ ┌──────────┐ ┌──────────┐ │ Events │ │ Shared │ │ (Kafka) │ │ Postgres │ │ │ │ (per-svc)│ └──────────┘ └──────────┘

Each service owns its database. Cross-service data needs flow through the event bus (Kafka) with an outbox pattern in each emitting service to guarantee at-least-once delivery. The migration plan calls for dual-writes during the transition window with a reconciliation job running hourly to detect drift.
